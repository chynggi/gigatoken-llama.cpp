### What this bench does NOT simulate

- Server slots (`-np 2`) - `llama-bench` has no concept of concurrent slots.
- `--kv-unified`, `--backend-sampling`, `--expert-hot-s -1` - server-only flags with no `llama-bench` equivalent.
- Speculative decoding (`-md`, `--spec-type draft-mtp`, `--spec-draft-n-max 2`) - `llama-bench` does not support a draft model or speculative decoding.
- `-c 81920` (the real context size) - `llama-bench` derives its working context from `-p`/`-n`/`-d` instead of taking an explicit `-c`.

Because of this, this plan's regression judgment is based on **raw pp/tg
throughput**, not on end-to-end server behavior with speculative decoding and
multiple slots.

## test-backend-ops

Command: `./build/bin/test-backend-ops`

Result: **16030/16031 tests passed. Exit code: 1** (not 0 - see below).

One pre-existing failure, on the CUDA0 backend:

```
FLASH_ATTN_EXT(hsk=576,hsv=512,nh=1,nr23=[20,1],kv=512,nb=1,mask=1,sinks=0,max_bias=0.000000,logit_softcap=0.000000,prec=f32,type_K=f16,type_V=f16,permute=[0,1,2,3],kv_view=1,v_is_view_of_k=0)
Backend CUDA0: FAIL
```

This is an MLA-style flash-attention shape (hsk=576, hsv=512, matching
DeepSeek-V2/V3-style latent attention head dims) failing on the RTX 3060
(compute capability 8.6). It is unrelated to CPU kernels and to this fork's
planned changes. The CPU backend itself is intentionally skipped by
`test-backend-ops` in its default "test" mode (it is the reference
implementation that other backends are compared against, so it is not
tested against itself) - this "Skipping CPU backend" message is normal,
not a bug.

Any later task that changes CPU kernels must not introduce **additional**
failures beyond this one pre-existing CUDA failure.

## ctest

Command: `ctest --test-dir build`

Result: **61/65 tests passed, 4 failed. Exit code: 8.**
Total wall time: 443.66 sec.

Failing tests and why (all pre-existing, all unrelated to CPU kernel hooks):

1. **test-tokenizers-ggml-vocabs** - fails to load several vocab-only GGUF
   fixtures (e.g. `models/ggml-vocabs/RWKV/ggml-vocab-rwkv-7-world.gguf`,
   `.../SPM/ggml-vocab-gemma-3.gguf`, `.../UGM/ggml-vocab-nomic-bert-moe.gguf`,
   `.../WPM/ggml-vocab-jina-v2-en.gguf`) with
   `gguf_init_from_reader: invalid magic characters: 'vers', expected 'GGUF'`.
   These files are git-lfs pointer text files in this checkout, not the real
   binary GGUF fixtures (git-lfs was never pulled) - an environment/checkout
   issue, not a code issue.
2. **test-unicode-regex-split** - `Shared regex mismatch for case 4: custom=16
   fallback=15`. A genuine pre-existing mismatch between the custom and
   fallback Unicode regex splitters, unrelated to this plan.
3. **test-jinja-py** - `ModuleNotFoundError: No module named 'jinja2'`. The
   Python `jinja2` package is not installed in this environment, so the
   cross-check against the reference Python Jinja engine cannot run. An
   environment/dependency issue, not a code issue.
4. **test-backend-ops** - the same pre-existing `FLASH_ATTN_EXT` CUDA failure
   described above.

The baseline for "zero new failures" going forward is these same four ctest
failures (16, 26, 36, 48) plus the one test-backend-ops case above - not zero
failures overall.
